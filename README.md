# bref Dictionary

A searchable, installable, offline-capable dictionary for **bref**, the alphabetic
shorthand system created by **Donald M. Volk**.

**→ [Open it](https://mtaran.github.io/bref-dictionary/)**

Built from the [Toki Pona Dictionary](https://github.com/mtaran/toki-pona-dictionary)
as a template: same single-page app shell, scored bidirectional search, service
worker and web manifest.

## What's in it

- **11,660 words** and **3,037 phrases** — the complete bref dictionary
- **Search either direction** — type English to get the brief, or type a brief to
  expand it. `because → bcs`, `bcs → because`
- **Filters** for direction (both / en→bref / bref→en) and entry type (all / words
  / phrases)
- **Also search the other side** finds entries whose *opposite* side matches, so a
  partial guess still lands
- Exact matches rank first, then prefixes, then substrings
- **Installable PWA** — add to home screen; the dictionary is cached, so it works
  with no network
- Light and dark themes; press <kbd>/</kbd> to jump to the search box

For the rules, the alphabet and reading practice, see the companion page:
**[bref — one-page reference](https://mtaran.github.io/bref-shorthand/)**.

## Data

`dictionary.json` is generated by `build_dictionary.py` from the author's word and
phrase lists in `source/`.

bref is a **bijection** — every brief expands to exactly one English word or
phrase — so each pair is stored once and both search directions are derived at
load time. That is the one structural departure from the Toki Pona template, whose
two directions carry genuinely different content. It keeps the offline payload at
~300 KB for 29,394 searchable entries. The build verifies on every run that no
brief expands to two different things (currently 14,697 briefs, 0 collisions).

Two defects in the source lists are corrected:

- `exam = xmexam = xm` — a typo; the intended brief is `xm`
- `government` — the FORWARD list gives `gvr`, the REVERSED list gives `gvt`;
  `gvt` is used, since `governments = gvts`

Where the manual's prose and the dictionary files disagree, the dictionary files
win, since that is what the author's EXPAND text-expander actually runs on.

Note for anyone else parsing these files: the word lists are English-first, but the
*phrase* lists use the opposite column order.

## Rebuilding

```sh
python3 build_dictionary.py   # regenerates dictionary.json, favicon.svg and the icons
```

No dependencies — the icons are rasterised by a small PNG encoder in the script.
